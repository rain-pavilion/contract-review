## 3. 必答 12 问（30–60 秒版）

1. F1 到底多少？ 见数据卡。补一句：“0.9505 成立，但条件是 11 份留出、174 个实体、两项金额后处理，必须和数值一起报。”
2. 3 分钟能达标吗？ “规则档能；模型档在 CPU 上不能。我们按档报告，没有拿规则档冒充满链路。”
3. 十万份怎么证明？ “合成 10 万条存储/调度压测通过；真实业务吞吐未验证，不把它写成 10 万份真实合同审查。”
4. 主体资格怎么核验？有真实数据吗？ “轻量资质图谱 + 人工导入证据 + 来源/时效/绑定；不直连工商/信用。没有外部权威材料就保持 unknown 或待核验，不假装通过。”
5. 人工金标做了吗？ “16 份真实合同/394 页、A/B 盲标+仲裁+冻结流程已建，完成行 0；没有虚构标注人员。下一步 50–100 份人工金标。”
6. 和 LawBench/ProvBench 比呢？ “官方数据/评分器不可得（ProvBench 404；LawBench 官方标注未公开/需 Linux 评分），只做了协议核验 + 自建等价评测，不报官方成绩。”
7. 创新点？和现有产品区别？ “三条硬约束 + 逐项反馈回环 + pending 状态与可审计归档；不是又一个合同审查 demo。”
8. 大模型幻觉怎么防？ “引文必须定位、评分只读、降级留痕；模拟端点 21 条无据缺陷全部被丢弃。”
9. 145 分钟太慢，有意义吗？ “这是 4-bit 8B 在 CPU 上的真实成本；已做分级复核 921.5 s→99.8 s（9.2 倍）；下一步 GPU/云端 API 与窗口预算。”
10. 申报书写 90%/3 分钟/十万，你们没做到，怎么解释？ “申报书原稿是 9 月提交的设计目标；修订版已把 F1 改为 85% 目标、3 分钟限定为规则档、十万份限定为合成压测。严格口径 0.9505 但依赖后处理与小留出，不加后处理 0.8782；模型档未稳定达标。我们没有把设计目标写成既成事实，失败证据也保留。”
11. 测试是不是自证？有第三方吗？ “工程测试只证明行为契约；法律质量要独立人工金标，所以我们不报准确率。这是我们主动承认的边界，也是下一步。”
12. 落地/团队分工/下一步？ “中小企业合同初审与律所辅助；当前实验室原型，无客户/收入；团队分工提前定好一人一句；下一步按‘金标→三臂→GPU→主体数据源’走。”
13. **CAIL 2026 不是新增了智能合同审查赛道吗？** “有，2026 新增，和我们的任务最接近；但它要报名、签保密协议，匿名拿不到数据包/金标，而且现在是复赛期，所以这次答辩不以它为依据。赛后可作为正式评测入口之一；它不覆盖主体真实性核验，也不等于五节点完整回环。”
14. **节点到底接没接智能体？** “接了：五个功能节点由独立任务级 Agent 承载，11/19 实际走 multi，8 类 Agent、15 个执行步骤、42 条消息、19 条通信边、0 条拓扑拒收；不是自由 ReAct 智能体，是任务级 Agent + 主脑调度 + 消息总线。”
