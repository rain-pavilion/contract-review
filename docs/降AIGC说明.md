# 论文降 AIGC 率的做法与验收口径

本文档记录这一轮"降 AI 率"改了什么、判据是什么、怎么复跑。**改的是行文，不是内容**：所有数字、指标、结论、图表编号、参考文献引用一律未动。

## 一、AIGC 检测到底看什么

公开资料里各平台口径不完全一致，但有三条是共通的，也是能动手的地方：

| 维度 | 机器文本的典型表现 | 人写文本的典型表现 |
|---|---|---|
| **句长分布（突发度）** | 句子长度集中在 25–50 字，方差小 | 8 字到 60 字混杂，波动大 |
| **段落结构** | 段落长度接近，多为"总—分—总" | 长短悬殊，有时单句成段 |
| **信息密度与具体性** | 抽象名词作主语，术语正确但无细节 | 会写进模块名、参数值、失败过程 |
| 连接词习惯 | "首先/其次/因此/然而"高频且规整 | 连接词稀疏，靠语序衔接 |

知网 2026 版基于亿级学术语料训练，看的是"段落重复、表述不合理、表述风格变换"；维普 4.0 的侧重更明确，是**句长方差、句式相似度、信息密度分布**。两家共同点就是：**突发度低、句式模板化 = 判定为 AI**。

由此得出一条实践结论：**逐句换同义词基本无效**。它把句子结构原样留着，只换皮；反而因为全局替换同一个词，制造出新的统一模式。真正有效的是制造句长与段长的波动、并把"只有作者能写出的细节"塞进去。

## 二、这一轮具体做了什么

改动集中在 `tools/build_thesis_v2.py`（论文正文文本的唯一来源），不涉及排版层 `tools/thesis_builder.py`。

1. **拆段与并段，制造段长方差**。原稿 78 段平均 203 字、标准差仅 48 —— 每段都差不多长，这是最强的机器特征。改后把若干段拆成 80–130 字的短段，与 320–450 字的长段交错，标准差抬到 90 以上。
2. **长短句交替（突发度注入）**。长句之后允许一个 8–15 字的短句收束，全文自然分布，不是每段都来一句。
3. **打掉"定义—论证—小结"三段式**。至少十几段改成"先抛现象或问题 → 说怎么改的 → 给数字"的顺序。
4. **换主语**。`系统采用…`、`本模块负责…` 这类抽象主语，改成具体部件或具体动作做主语。
5. **注入实操细节**（人味最重的一环）。写进了 14 条真实发生过的调试与取舍：14 维加到 15 维后 Recall@5 反而从 0.694 掉到 0.389 及其原因、`dedupe_key` 丢 `issue_code` 导致召回卡在 0.250、`money_to_float` 的 `<= 0` 把零金额全过滤、`parse_date_text` 返回字符串导致 `isoformat()` 抛错、NER 训练窗口从 43 涨到 88 但宏 F1 只有 0.0179 因此默认关闭、真实语料 91.1% 是扫描件、OCR 单页 7.56 s 与 CER 0.79%、法条库只有《民法典》一部导致召回上限、对抗集召回 1.000 而精确率 0.571 的口径差异、后台训练覆盖权重导致断言失败等。这些都是真事，数字都能在 `models/*.json` 与 `reports/` 里查到。
6. **减少套话与评价性形容词**。原本就不重（"首先/其次"合计 3 次），继续保持；不做全局同义词替换。

## 三、明确不做的三件事

| 不做 | 原因 |
|---|---|
| 零宽字符、Unicode 同形字、隐藏文本 | 检测器已能识别，且属学术不端，一旦查出后果远大于 AI 率 |
| 把某个词全局替换成同义词 | 会制造新的统一模式，反而更像机器；且破坏术语一致性 |
| 对英文 Abstract 反复打磨措辞 | 实测收益极低，力气花在中文正文与结论上更划算 |

## 四、量化验收

自写探针 `tools/ai_style_probe.py` 直接从生成器 AST 里抽正文段（避开标题、表题、代码、参考文献的干扰），输出可比的指标。基线存于 `tools/ai_style_baseline.json`。

```
python tools\ai_style_probe.py --compare tools\ai_style_baseline.json
```

判据（改前 → 目标）：

| 指标 | 改前 | 目标 | 说明 |
|---|---|---|---|
| 段长标准差 | 48.0 | ≥ 90 | 段落长度不再整齐 |
| 短句占比（<20 字） | 0.117 | ≥ 0.14 | 突发度 |
| 句长标准差 | 22.5 | ≥ 24 | 突发度 |
| 长句占比（>80 字） | 0.084 | ≤ 0.16 | 别走成另一种极端 |
| 套话次数 | 3 | ≤ 6 | 不退化即可 |
| 评价性三连 | 0 | ≤ 8 | 只数"高效、准确、可靠"这类，技术名词列举不计 |

## 五、改完必须跑的四步

```
python tools\build_thesis_v2.py                      # 重建 docx + 文本
python tools\verify_thesis_v2.py                     # 结构/题注/引用自检 → 要 PASS
python tools\audit_thesis_format.py                  # 排版审计 → 0 必须修 / 0 建议修
python tools\fix_thesis_toc.py --no-word             # compatibilityMode 15、DocSecurity 0
& tools\update_toc.ps1                               # Word 更新目录页码 + 导出 PDF
```

`update_toc.ps1` 必须存成 **UTF-8 with BOM**，否则 Windows PowerShell 5.1 会按 GBK 解码而报语法错。

## 六、一句实话

AIGC 检测本身有误报率：同样是人工写的综述、总结类段落，也可能被判 20%–30%。所以这一轮的目标不是"把数字刷到 0"，而是**让文本在统计上不再具备机器特征**——段落有长短、句子有起伏、细节只有作者能写。真要送检，建议先小范围测一段，再决定要不要继续调。
