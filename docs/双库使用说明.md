# 合同、法条与用户库使用说明

## 启动与登录

在项目根目录双击 `start-libraries-web.cmd`，或在 PowerShell 中运行：

```powershell
.\start-libraries-web.cmd
```

浏览器入口为 <http://127.0.0.1:8619/>。默认关闭主大模型通道，不加载 8B；可完成登录、合同上传与版本管理、档案查询、法条导入、来源采集、核验和发布。提交审查时如需实际 LegalOne-8B 模型，先停止当前网页服务，再运行：

```powershell
.\start-libraries-web.cmd --with-model
```

模型需要本机已备好的权重、运行时和依赖；就绪后网页才启动。可追加 `--no-browser`，或用 `--port 8621` 指定其他网页端口。关闭服务使用控制台 `Ctrl+C`。同端口已有服务时启动器会尝试复用，切换数据目录或模型模式前先停止旧服务。

交付管理员凭据文件由交付初始化步骤生成在 `data/libraries/private/administrator.json`。在本机查看该文件的 `username` 和 `password`，填入登录页；本文不记录口令。普通用户可以在登录页点击“注册账号”，也可由管理员创建。已经初始化过的库无需再执行 `init-admin`。

## 三个数据库与目录

专用启动器把本次进程的目录固定到项目下 `data/libraries`；不修改现有启动器或环境配置文件。

| 内容 | 项目相对路径 | 用途 |
| --- | --- | --- |
| 合同库 | `data/libraries/contracts.sqlite` | 合同原件及版本、审查任务、报告、管理员反馈与业务审计，仅保留用户编号引用 |
| 法条库 | `data/libraries/laws.sqlite` | 法律文件、来源、草稿及发布版本、条文和采集记录 |
| 用户库 | `data/libraries/users.sqlite` | 用户账号、密码哈希、角色、启用状态、登录会话与账号审计 |
| 法条来源原件 | `data/libraries/laws_raw/` | 已采集或导入的来源快照 |
| 审查法条快照 | `data/libraries/laws_snapshots/` | 本次审查实际采用的不可变 JSONL 与校验值 |
| 兼容工作台归档 | `data/libraries/legacy-workspace.sqlite` | 兼容功能产生的新归档，与旧工作台数据库隔离 |
| 模型调用记录 | `data/libraries/model-audit.sqlite` | 当前入口产生的模型审计记录 |
| 主体事实 | `data/libraries/subject-facts.json` | 当前入口使用的主体事实文件 |
| 本机管理员凭据 | `data/libraries/private/administrator.json` | 本机交付凭据，勿提交版本控制或分享 |

启动器同时指定 `ZLQL_LIBRARY_ROOT`、`ZLQL_CONTRACT_LIBRARY_PATH`、`ZLQL_LAW_LIBRARY_PATH`、`ZLQL_USER_LIBRARY_PATH`、`ZLQL_STORE_PATH`、`ZLQL_MODEL_AUDIT_PATH` 和 `ZLQL_SUBJECT_FACTS_PATH`。这些设置只作用于启动器及其子进程。原有 `zhilv_qiling_v2/reports/*.sqlite` 和 `data/reviews.sqlite` 不因启动本入口而被迁移或覆盖。

旧版合同库内的账号和会话会在升级时迁入独立用户库，用户编号和合同归属保持一致；重复启动不会重新导入已撤销的会话或覆盖新密码。合同库与用户库需要成套备份和恢复；已有合同归属的用户库缺失或路径配置错误时，系统会拒绝初始化，避免生成错误的账号映射。

## 注册账号

登录页点击“注册账号”，填写用户名、密码和确认密码。用户名为 2–64 位中文、字母、数字、下划线、点或短横线；密码为 12–512 位，两次输入须一致。成功后返回登录页，用户名已填好，输入密码即可登录。注册不要求邮箱或手机号。

公开注册创建启用的普通用户账号，只能访问本人合同和报告。注册页面不提供管理员角色；管理员仍通过“用户管理”创建账号或调整角色。首次管理员尚未初始化时，公开注册入口关闭。注册有频率限制，重复用户名不会覆盖已有账号。

需要暂停公开注册时，在 PowerShell 设置后启动网页服务：

```powershell
$env:ZLQL_PUBLIC_REGISTRATION = '0'
.\start-libraries-web.cmd
```

设置为 `1` 可重新开放。修改后需重启已在运行的服务；管理员创建账号不受此开关影响。

## 账号与权限

| 操作 | 普通用户 | 管理员 |
| --- | --- | --- |
| 上传、查看原件、提交审查、读取报告 | 仅自己的合同 | 全部合同 |
| 修改合同信息或新增修订版本 | 不允许 | 允许，保留历史原件 |
| 删除合同 | 不允许 | 软删除，历史版本和报告保留 |
| 保存风险复核意见 | 可读取自己报告的管理员结论 | 可追加意见，原报告不变 |
| 浏览法条 | 已发布版本 | 包括未发布草稿 |
| 导入、采集、核验、发布法条 | 不允许 | 允许 |
| 迁移旧档案、账号管理、查看审计 | 不允许 | 允许 |

管理员在网页的账号管理区域创建普通用户，输入不少于 12 位的口令；也可重置口令、停用账号、调整角色。修改口令、停用或变更角色后，原登录会话失效，需要重新登录。系统拒绝停用或降级最后一名有效管理员。普通用户即使知道其他合同或报告的链接，也无法打开。

## 合同操作与报告

1. 登录后进入合同库，上传合同并填写标题、领域、地区。单个文件上限 40 MiB，支持 TXT、Markdown、PDF、DOC/DOCX、HTML 及常见图片；空文件不能上传。
2. 打开合同详情查看版本和原件。管理员修改文件名或内容会产生新版本；仅修改标题、领域、地区会记录审计，不新增内容版本。原件可按历史版本读取。
3. 提交审查时选择合同版本及法条适用范围。任务会绑定提交时的合同版本和法条快照；后续合同修订或法条更新不改变该任务已有输入。
4. 在任务列表查看排队、运行、完成或失败状态；完成后打开报告。每次审查单独保存报告，不覆盖上一份结果。默认未加载主大模型的运行不应当作实际 8B 模型审查。
5. 管理员在报告风险项追加确认、误报或待复核意见；合同所有者可以查看。意见另行保存，不覆盖机器原始评分及报告快照。

旧库无法识别原上传者的档案统一归管理员管理，始终仅管理员可见，不分配给首位普通用户。迁移会保留原报告载荷；存在正文时保存文本快照，但无法据此还原 DOCX/PDF 原上传文件。详情中的“原件不可得”标记不会因为保留了正文而消失。

## 本机 CLI：初始化、迁移与账号

以下命令在项目根目录的 PowerShell 运行。`--root` 和 `--admin-credentials` 是全局参数，放在子命令之前。CLI 默认采用 `data/libraries`；如果当前终端设置过 `ZLQL_CONTRACT_LIBRARY_PATH`、`ZLQL_LAW_LIBRARY_PATH` 或 `ZLQL_USER_LIBRARY_PATH`，先确认它们指向本次实例，避免操作其他实例。

查看路径和状态：

```powershell
.\.venv\Scripts\python.exe -m zhilv_qiling_v2.library_cli --root .\data\libraries status
```

仅为全新空库生成首位管理员及本机凭据文件；现有库会拒绝重复初始化：

```powershell
.\.venv\Scripts\python.exe -m zhilv_qiling_v2.library_cli --root .\data\libraries init-admin --username admin --generate-credentials .\data\libraries\private\administrator.json
```

创建普通用户时按提示交互输入新用户口令，不把口令写入命令行：

```powershell
.\.venv\Scripts\python.exe -m zhilv_qiling_v2.library_cli --root .\data\libraries --admin-credentials .\data\libraries\private\administrator.json create-user --username colleague --role user
```

导入指定旧工作台和法条 JSONL，可重复传入 `--workspace` 或 `--jsonl`：

```powershell
.\.venv\Scripts\python.exe -m zhilv_qiling_v2.library_cli --root .\data\libraries --admin-credentials .\data\libraries\private\administrator.json migrate --workspace .\zhilv_qiling_v2\reports\workspace.sqlite --workspace .\data\reviews.sqlite --jsonl .\data\法条结构化数据.jsonl
```

不提供来源参数的 `migrate` 会检查当前主工作台、答辩工作台、旧审查库及预设法条文件；缺失文件会记录为缺失，不凭空生成来源。迁移只读旧 SQLite，同一路径、表和记录再次导入会跳过；混合包含完整报告和摘要档案的旧库会遍历两张表。导入法条成为待核验草稿，不会自动发布旧的未知效力记录。

## 法条采集、核验与发布

先查看当前配置中的官方来源 ID，再选择来源做有界采集：

```powershell
.\.venv\Scripts\python.exe -m zhilv_qiling_v2.library_cli --root .\data\libraries sources
.\.venv\Scripts\python.exe -m zhilv_qiling_v2.library_cli --root .\data\libraries --admin-credentials .\data\libraries\private\administrator.json crawl --source labor_contract_law --max-documents 1
.\.venv\Scripts\python.exe -m zhilv_qiling_v2.library_cli --root .\data\libraries --admin-credentials .\data\libraries\private\administrator.json crawl --max-documents 11
```

`--source` 可重复指定，ID 来自 `sources` 输出。来源定义位于 `zhilv_qiling_v2/law_sources.json`。采集会保留原来源和结果记录；网页能访问或下载成功只说明来源可用，不等于该法律当前有效。采集失败不会成为可检索的有效法条。

在网页或命令返回结果中取得待审核版本 ID，打开来源原件，对照发布机关、条文、施行日、废止或失效状态、地区和领域。确认后记录核验结果；以下日期、地区、领域、依据均需替换为本次实际核对内容：

```powershell
$version = '待核验版本ID'
.\.venv\Scripts\python.exe -m zhilv_qiling_v2.library_cli --root .\data\libraries --admin-credentials .\data\libraries\private\administrator.json verify --version $version --validity effective --effective-from '2024-01-01' --region '全国' --domain labor --evidence '替换为实际核验的官方来源URL及核验说明'
```

`verify` 记录管理员核对结果，不自动判断法律效力。无法确认时用 `--validity unknown`；其他可选状态为 `abolished`、`expired`、`not_yet_effective`，必要时填写 `--effective-to`。已发布版本修改元数据会生成新的草稿，后续发布应使用 `verify` 返回的新版本 ID。

确认元数据及原件后，单独执行发布：

```powershell
$version = '核验返回的版本ID'
.\.venv\Scripts\python.exe -m zhilv_qiling_v2.library_cli --root .\data\libraries --admin-credentials .\data\libraries\private\administrator.json publish --version $version --note '替换为本次发布说明'
```

草稿不对普通用户展示，也不进入默认审查检索。发布时会生成可追溯快照；只有满足效力、核验、适用日期及范围筛选条件的已发布条文进入默认检索。未知、已废止、已失效或未施行记录即使发布供查阅，也不会因此被当作当前有效依据。没有匹配条文时，应补充并核验所需来源后再提交审查。

法条可覆盖通用、建设工程、房地产、贸易、公司、金融、劳动、知识产权、数据、政府采购等领域，领域可继续扩展；当前库和官方来源清单并非所有法律或行业的穷尽集合。
