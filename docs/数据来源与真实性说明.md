# 数据来源与真实性说明

一句话：**法条是真的，真实合同是真的（给了链接，实测可打开），合成样本是合成的且已逐份标注**。
下面每一条都给出可复核的字段与命令，不靠"我记得"。

| 条数 | **1260 条** | `第一条` ~ `第一千二百六十条`，无缺号 |
| 法律 | 《中华人民共和国民法典》 | `law_name` 单值 |

这是当前检索覆盖率的主要上限（详见 `docs/CHANGELOG-v1-v2.md` 的"不足"一节）。

## 三、合成样本（`data/generated_contracts/`，50 份）

| 子集 | 份数 | 生成方式 | 标签 |
|---|---|---|---|
| `samr_multi_template_2025` | 20 | 按 5 类市场监管合同范本（房屋租赁/委托/中介/数据提供/保管）程序化填充 | `manifest.json` 的 `records[]` |
| `samr_multi_template_2025/adversarial` | 10 | 在范本上**定向注入**缺陷 | `records[].issue_codes[]`（27 码子集）← 评测金标准 |
| `samr_sdf_2025_0002` | 20 | 山东商品房预售/买卖长合同模板 | `records[].risk_type` |

**为什么必须说清楚**：这三组是**合成的**，用来做"可控注入 → 可量化召回"的实验，不是真实签署的合同。
66 份（63 真实 + 50 合成 = 113，另 3 份为 v1 早期重复项不计）在 `train.py` 里按文档切分训练/验证，避免条款泄漏。

## 四、一条命令复核全部

```bash
python zhilv_qiling_v2/reports/experiments/demo_kb.py     # 库规模 + 真实合同端到端 + 条款探针
python -m zhilv_qiling_v2.cli doctor                       # 语料/模型/依赖是否在位
python zhilv_qiling_v2/reports/experiments/corpus_stats.py # 63 份真实合同的页数/扫描页分布
```

`demo_kb.py` 的输出已存档在 `zhilv_qiling_v2/reports/kb_demo.txt`。

## 五、局限（写在明面上）

1. 单句/裸条款检索的邻域质量不如真实条款：基准里 `Recall@5=0.6944`，而随手写的短句可能出现"贴标签对了、条文不完全对"的情况（探针里可见）。原因是没有上下文与要素约束，且金标准本身按标签族构造。
2. 真实政采合同偏离 5 类范本较远，条款切分粒度更粗，风险判定偏保守（同一份 17 条风险里含重复码，已按 `dedupe_key` 去重但不同 issue 会保留）。
3. 法条只有《民法典》一部，检索覆盖率的上限由题库语料决定，不由模型决定。
