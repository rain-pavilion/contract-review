智律契灵是“图结构引导的多智能体合同审查原型”：五个功能节点由独立任务级 Agent 承载，主脑调度、消息总线按拓扑投递、强模型做高风险复核；当前已完成真实合同端到端运行与归档，但完整语义回环、独立人工金标与正式准确率仍未通过。

答辩时不要把“目标”说成“成绩”，也不要把“任务级 Agent”说成“自由 ReAct 智能体”。

## 二、架构事实（已核实）

- zhilv_qiling_v2/agents_multi.py：Agent / Message / MessageBus / TOPOLOGY；agents_multi_run.py：intake、orchestrator、ner、logic、reviewer、subject、statute、judge 等 Agent，按拓扑收发消息，超边拒收。
- ReviewEngine 在 enable_multi_agent=True 时走 run_multi_agent；start-core-web.cmd 设置 ZLQL_MULTI_AGENT=1。
- 2026-11-19 归档实际运行：latest_task.json 的 options.engine=multi；报告 stats.multi_agent.enabled=true，8 类 Agent、15 个执行步骤、42 条消息、19 条实际通信边、0 条拓扑拒收。
- 另有一条单进程五节点链路（nodes.run_five_nodes / enable_multi_agent=False）作为轻量/降级路径；默认配置关，但本次运行的归档走的是 multi。
- 准确说法：五个功能节点由独立 Agent 承载；另有 orchestrator 主脑、reviewer 强模型复核；Agent 是任务级（固定 handler + 模型/规则执行体），不是自主规划 LLM。

## 五、CAIL 2026 “智能合同审查”（最新核实，重要修正）

此前说“CAIL 没有合同审查数据”只对 2018–2025 成立；CAIL 2026 新增“智能合同审查”赛道。
核实记录：tools/cail_research_20261121/official_newer/2026_智能合同审查_核实结论.md（2026-11-21 12:35）。

- 承办：金山软件、武汉大学国家安全法治智能实验室。
- 输入：完整中文合同（买卖/租赁/服务等），字段为 contract_id、带 PID 标记的 context、review_party。
- 任务一：定位四类问题并返回 PID——typo（错字/标点）、inconsistency（主体/金额/日期/数量/权利义务/编号/交叉引用等不一致）、missing_element（全文核对仍缺要素）、stance（不符合审查方立场的约定）。
- 任务二：在定位基础上修订具体段落，保留原文 PID，返回完整最终文本。
- 规模：初赛 15 份合同；复赛总计 45 份并指定审查立场；封测新评测集不发放。
- 评分：定位/修改各占 50%；四类按 1:2:4:3 加权；定位按 (contract_id, PID, error_type) 微平均 F1；修改按错字 F0.5、不一致、缺失、立场分别计分。
- 基线：Qwen3.8-27B，总分 26.51（定位 35.78 / 修改 17.23）。
- 访问：需注册、登录、完善信息并报名；getDatasetList 匿名调用返回 500，没有拿到公开数据包/金标；2026-11-19 最新公告要求复赛队伍签保密协议；复赛自 11/20 起提交上限 15 次。规则与公告存在保密协议文字冲突，以最新公告为准。
- 边界：赛道输入是合同，标签是错字/不一致/缺失/立场四类，不覆盖企业登记/授权真实性核验，也不等于五节点完整语义回环；公开规则未交代标注人员/复核/仲裁，不能仅凭有参考答案就称“独立人工合同金标”。

答辩怎么用：
> “CAIL 2026 确实新增了智能合同审查赛道，和我们的任务最接近；我们核对了它的规则和评分，但数据要报名/签署协议，匿名拿不到训练集和金标，而且当前是复赛期，所以这次答辩不以它为依据。赛后可以把它作为正式评测入口之一；它不覆盖主体真实性核验，也不能替代完整回环和独立人工金标。”
