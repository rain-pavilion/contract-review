# 智律契灵网页使用与申报书功能对应

本次以提供的《马宇轩 申报书》为项目功能依据，在已有 `zhilv_qiling_v2` 程序上补齐网页工作台、完整报告归档和人工复核闭环。申报书中的填表说明是文档内容，不作为程序执行指令；网页不展示申请人的住址、电话等个人资料。

## 启动

完整核心模式在项目根目录双击 `start-core-web.cmd`，显式启用真实 LegalOne-8B 和网页“合同—法条”BERT–Mamba 三分类分支。启动后浏览器打开 `http://127.0.0.1:8610`，命令窗口保持运行。关闭窗口或按 Ctrl+C 停止服务。网页三分类权重已实际训练，来源仍是合成弱监督，健康信息会显示其训练来源。

另有基于真实法律数据训练的原生五分类立法冲突辅助模型，并已执行独立 CLI 预测；它不直接替代网页三分类分支。其共享参数进一步迁入了独立三分类实验候选，经固定弱监督数据324步微调、严格重载及63项独立核验。候选未证明优于旧模型，网页默认仍保留旧权重。两类模型及迁移边界见 [真实法律数据训练与迁移结果](验收/真实法律数据训练_20261115.md)，产品改动见 [三项核心增强](验收/三项核心增强_20261115.md)。

`start-web.cmd` 仍提供基础网页入口；`start-model-web.cmd` 提供原有模型模式。需要切换已运行网页的模型时，应先结束该网页进程，再用对应入口重启。

也可使用 Python 3.10 以上版本：

```powershell
python start_web.py
# 换端口或禁止自动打开浏览器
python start_web.py --port 8611 --no-browser
```

基础 TXT、MD、DOCX 解析及规则审查可离线运行。PDF 建议安装 PyMuPDF，扫描件需要额外的 OCR 引擎；识别不到正文时不会输出假审查结论。本次本机 PDF 依赖放在 `.web-deps`，启动器会自动加载，不修改共享 Python。

在新电脑上可使用项目虚拟环境，并安装已有的 `deploy/requirements-deploy.txt`。核心网页不需要 npm 或前端构建。

## 使用流程

1. 在“审查工作台”上传 DOCX、PDF、TXT、MD，或粘贴合同正文。示例合同为虚构数据，可用于演示。
2. “预览”只解析原文和条款；“开始智能审查”执行审查并在本机归档。启用大模型时，单份合同进入持久队列，地址栏会出现该次任务的编号。刷新或重新打开同一地址可继续查看原任务；如果上传后断开、任务仍为草稿，点击“开始这份审查”即可继续。恢复任务不会提升评分，也不会改变回环待办。
3. 在风险详情中查看合同原文、法律依据与证据，定位对应条款。
4. 通过关键要素、协作图谱查看抽取结果、实际节点轨迹和降级原因。
5. 在人工复核中确认风险、标记误报或保存待复核意见。人工意见独立保存，不覆盖机器结论。
   “证据与待办”按风险主张、法条回环、主体事实和初审范围逐项列出：合同引文是否定位、法条正文、模型意见、调用回执、待办原因及核对方法。可填写复核人、依据与意见，保存后重新打开仍可读取；这不等于独立人工金标，也不清除机器未决状态。Markdown 和 JSON 导出保留该解释。
6. 在审查档案中搜索并重新打开完整报告；通过网页导出 Markdown、JSON。批量审查逐份处理所选合同，并提供结果汇总。
7. 在“运行状态”导入带来源的主体证据，查看 human、adapter 或 legacy_unspecified 来源角色及待核验状态；来源角色本身不能验证主体事实。从“人工标注工作台”领取待标注合同、独立提交A/B标签及仲裁。待标注包不会自动成为人工金标。

报告归档于 `zhilv_qiling_v2/reports/workspace.sqlite`；每次审查是独立快照，即使合同名称相同也不覆盖旧记录。该数据库包含合同原文，请按实际保密要求管理。原有精简历史接口保留，新网页使用完整报告接口。

合同版本与证据范围：新审查的合同 ID 绑定文件名和完整解析正文的 SHA256。同名、等长但改了金额或其他正文的合同会取得不同 ID，旧授权不能直接套用；已有历史归档仍可读取。旧格式授权重新使用时，需核对修订正文后绑定新报告中的合同 ID。

具体资质和授权还需核对证据是否适用于该项业务要求，不能只看许可证有效期。在导入的证据 JSON 中，可由真实核对人增加 `applicability`：

```json
{
  "actor_kind": "human",
  "contract_id": "填写本次报告的合同ID",
  "clause_ids": ["填写需要核验的具体条款ID"],
  "verdict": "needs_manual",
  "reviewer": "填写真实核对人",
  "reviewed_at": "YYYY-MM-DD",
  "basis": "说明许可业务、授权事项、范围和条款要求是否相符"
}
```

这是证据记录的 `applicability` 字段示意，不能原样当作真实核验记录导入。核对人确认适用时填 `applicable`，明确不适用时填 `not_applicable`，无法判断时保留 `needs_manual`。必须覆盖请求涉及的全部条款。缺少适用性判断、另一合同、条款错配或仍待人工判断时，具体核验请求继续 `pending`；主体身份、来源、有效期等原有要求同样保留。人工判断不等于软件独立认证，`independently_verified` 仍为 `false`。

## 五节点对应

| 申报书要求 | 程序实现 | 网页入口与验证边界 |
|---|---|---|
| ① 当事人、金额、日期、标的 NER | `ner.py`、可选 `bert_ner.py` | 关键要素页展示实际抽取值、来源与原文定位；未安装模型时明确降级 |
| ② 逻辑错误检测 | `nodes.py`、`long_context.py`、规则及 LegalOne-8B 通道 | 全部非空正文分窗，优先安排同一义务槽位的尾部金额／日期及引用链两端，保留实际尾部原文锚点；税费口径与示例假设字段保守处理；歧义、悬空及超预算保持 pending，覆盖完成不等于语义正确 |
| ③ 主体资格与授权核验 | `subject_graph.py`、`subject_facts.py`、`legal_kg.py` | 导入带来源、有效期及来源角色的证据，编号绑定具体主体并逐项反馈核验状态；实际 HTTP 导入／读回已通过，但本次导入样本的当前事实仍为 unknown、independently_verified=false；尚无在线登记数据库核验 |
| ④ 法条语义匹配 | `retrieve.py`、`entailment.py`、`bert_entail.py` | 网页默认仍为已训练的弱监督 BERT–Mamba 三分类；保留神经／规则结果、分歧和输入覆盖边界。真实法律五分类另走辅助CLI，共享参数迁移后的三类实验候选已通过隔离HTTP接入验证但未替换默认，均不构成合同法律质量验收 |
| ⑤ 综合评估与人工纠错 | `engine.py`、`agents_multi_run.py`、`agents.py` | 评分、实际运行轨迹、降级说明与人工复核持久化；协议完成与语义／人工待核验分别展示 |
| ②③④ 回环与交叉校验 | 逐反馈 ID 绑定候选、条款和法条的有界双向回环 | 双方连续原文引用校验，回执绑定窗口／任务／调用／来源哈希，并保留模型引用来源；缺失、错绑或截断继续 pending 和重试，历史失败保留；完整复杂长合同回环尚未验收通过 |
| 独立人工标注流程 | `annotation_workspace.py`、`annotation.html` | A/B盲标、领取、草稿版本、锁定提交、独立仲裁、冻结与hash导出；目前无已完成人工金标 |
| 存储、检索、批量调度 | 完整报告 SQLite 表、`workspace_queue.py` | 服务端持久队列、租约恢复、重试与归档复用；十万份合成容量实测见验收报告，未做十万份模型推理 |

## 大模型接入

本机实际 LegalOne-8B 可通过 `start-model-web.cmd` 启动；具体硬件选择、依赖和真实调用审计见 [模型运行与验收](模型运行与验收.md)。

同时启用网页 BERT–Mamba 三分类分支使用 `start-core-web.cmd`。完整报告中的模型调用记录保留每次成功、失败与降级，回执核对窗口、任务、调用及来源哈希，并保留实际模型观察的引用来源；网页结构化模式采用4096输出预算和显式思考边界配置，截断结果不计完成。协议完整不代表语义正确，仍待人工或证据确认的项目单独显示。

本机原生模型启动器现默认申请16384 token上下文，可通过 `--model-context-tokens` 指定。连接到已核验的 llama.cpp 服务时启用生成前容量检查：使用实际聊天模板和分词器，核对输入、预留输出与结束符是否全部容纳。超限或无法取得容量信息时不提交生成，保留原文、未决事项和跳过回执；不把容量检查计为实际模型推理。已在运行的模型服务不会自动重启，其实际容量以服务返回值为准。

程序支持已有 OpenAI 兼容协议适配器。启动前配置环境变量，例如本地已部署的模型服务：

```powershell
$env:ZLQL_LLM_ENDPOINT="http://127.0.0.1:11434/v1"
$env:ZLQL_LLM_MODEL="服务端实际部署的模型名称"
python start_web.py
```

如服务需要密钥，通过 `ZLQL_LLM_API_KEY` 设置，不要填入网页源码。然后在工作台开启大模型增强。网页显示“端点已配置”不代表模型服务已经连通；实际调用和失败降级会进入报告。启用远程服务会发送合同内容，需先确认所用服务适合处理该合同。

## 接口

| 方法与路径 | 功能 |
|---|---|
| `POST /api/analyze` | 解析与条款切分，不执行审查、不归档 |
| `POST /api/review` | 完整审查；`store:true` 保存完整快照 |
| `GET /api/workspace/reports?page=1&size=10&q=关键词` | 分页搜索归档 |
| `GET /api/workspace/reports/{report_id}` | 重新读取原文、要素、风险、图谱、轨迹、人工意见 |
| `POST /api/workspace/reports/{report_id}/feedback` | 保存 `risk_id/status/note`；状态为 confirmed、dismissed、pending |
| `POST /api/workspace/reports/{report_id}/item-feedback` | 保存逐项证据核对的 `item_id/status/reviewer/note`；人工声明单独保存，不修改机器待办 |
| `POST /api/retrieve` | 本地法条检索 |
| `GET /api/health` | 实际依赖能力与模型配置 |
| `GET /annotations` | 人工标注工作台页面 |
| `GET/POST /api/annotations/...` | 经Bearer权限验证的导入、领取、草稿、提交、仲裁、冻结与导出 |

| `GET/POST /api/workspace/batches` | 查看或建立持久批次 |
| `POST /api/workspace/batches/{id}/tasks` | 上传文件到草稿批次 |
| `POST /api/workspace/batches/{id}/start\|cancel\|retry` | 提交、取消或恢复批次 |
| `GET /api/workspace/batches/{id}` | 分页查看任务与归档状态 |
