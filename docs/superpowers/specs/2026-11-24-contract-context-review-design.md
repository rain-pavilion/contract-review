# 跨条款与跨附件上下文审查

用户授权：按本会话已讨论的“要素提取＋图结构约束＋跨文件组合审查＋证据追溯”补足现有项目功能。信息齐全性的新思路尚未提供，本轮保留可调用接口及明确的未评估状态，不猜测其实现。

## 实现范围

- 沿用 `zhilv_qiling_v2` 的 source-bound `fact_slots`、`proposition_graph`、审查点回执与合同包来源元数据。
- 新增统一 `evaluate_contract_context(contract, config=None, *, completeness_check=None) -> dict`；单智能体与多智能体均在 `ReviewEngine.run` 接入。
- 输出使用 `stats.contract_context_review`，包括 `schema_version`、`execution_status`、`source_documents`、`proposition_graph`、`constraints`、`findings`、`checks`、`completeness`、`summary`。
- 图约束核查条款标识、来源与引文绑定、关系端点；缺失、重复、篡改不产生自动通过结论。
- 组合审查消费已有显式前置条件环和金额关系，并新增有界的“验收→付款、默认验收期限、必要测试时间”的三证据时序检查。
- 不按文件顺序、同名事件或相同金额自动认定适用范围或优先级；例外、否定、修订、OCR未核实及适用范围不明保留人工核对原因。
- 每条组合发现保留具体证据、原文偏移及哈希、来源、推导步骤、假设和待核原因。发现是有界文本线索，不是自动法律确认。
- 新回执并入既有审查点评估；独立上下文页面与 Markdown 导出显示证据链，旧报告缺少字段时保持兼容。既有风险计分与主体/法律分支不重构。
- 修正旧结构图跨来源同编号引用覆盖问题，歧义引用不静默任选。

## 验证

先用失败测试证明新增行为缺失，再实现：三证据组合、同范围/不同范围、例外与优先约定、缺证据、篡改、重复ID、跨来源同编号、单/多智能体集成、API归档读回及前端真实渲染和转义。回归采用离线配置，不读取密钥、不发起模型调用。

当前工作区存在大量既有未提交实现，原地局部增量修改并保存本轮基线；不清理、不覆盖、不提交其他变更。已有设计讨论及本次实施指令即为本轮实施依据，不另设重复审批。
