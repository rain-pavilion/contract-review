# 第一节点主脑调度设计

用户已确认六核心智能体方案，并要求主脑改为第一节点。核心节点编号为：①主脑规划与调度、②要素抽取、③逻辑审查、④主体审查、⑤法条匹配、⑥综合评估。intake 与 reviewer 是辅助角色。

②和③为主脑分别派发的同层职责分支：②提取主体、金额、日期等结构化信息，③处理合同上下文、跨条款依赖和逻辑风险。逻辑节点不依赖②节点先执行或向其发送要素消息；两个分支的产物在后续核验和综合评估中汇合。当前准备合同时仍生成基础要素供规则检测共享，且执行器仍按资源顺序运行两个分支，职责并列不等同于已实现并发推理。

主脑复用现有 orchestrator 身份、消息总线和有界回环。必需业务任务依赖仍由执行器保证，主脑可按初始任务、风险发现及反馈状态，从登记的模型池选择 logic/judge/reviewer 的模型，指定局部复核范围，并请求人工处理。模型不得指定任意 URL、跳过必需审查、修改评分或清除 pending。

新增独立 planner 配置与模型池，模型池通过受控配置登记能力及端点。云端规划输出经过结构校验和模型能力校验后才执行；缺配置、禁用大模型、格式错误、超时或调用预算耗尽时使用现有规则计划并明确留痕。规划输入使用有界摘要，避免每轮重复发送全文。模型计划与实际路由进入报告；密钥不进入提示、总线或报告。

保留 node1_ner 等历史内部标识，新增核心节点编号元数据表达当前六节点，保证归档兼容。网页优先显示六核心节点，能区分规则调度与模型决策，展示选择原因、复核范围和未解决事项。基础审查流水线继续展示其实际五业务阶段。

验证包含：实际选中模型配置进入业务执行体、禁止未登记路由、异常回退、规划预算、pending 保留、报告脱敏、历史报告渲染及六节点显示。使用离线替身或本地 HTTP 验证，不进行真实外部调用。云端模型的质量与性能须在配置凭据后单独实测。
