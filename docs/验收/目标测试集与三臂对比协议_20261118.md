# 目标测试集与三臂对比协议

日期：2026-11-18
适用阶段：P1 独立人工标注目标测试集 → P2 三臂对比 → P3 归因 → P4 针对性训练。
前置顺序：先完成 P0 反馈任务完整执行（见 [当前结论与下一阶段](当前结论与下一阶段_20261118.md) 与 `tools/acceptance_results/feedback_completion_20261118_v1/receipt.json`）。本协议不产生任何未实测的成绩。

## 一、目标测试集（P1）

### 1.1 数据来源与现状

- 来源包：`docs/验收/真实合同待标注包_20261117/`，从 63 份公开公告中筛出 16 份合同、394 页（271 页有非空文字层、2 份纯图片合同需 OCR），共 788 个来源文件。
- 9 张 A/B/仲裁标注表、3 份工作簿、3 个标注界面已生成；人工标签字段全部为空；`independent_gold=false`。
- 32 个来源链接本轮核验失败（HTTP 502 / SSL EOF），来源可获取性记录保留，不能据此认定来源真实性已核。
- 现有 18 条旧候选为合成流程样例，不能进入目标测试集；`human_acceptance_actual_v2` 已拒收其作为人工金标。
- 外部人工审查参考样本（非本项目金标）：已抓取全国合同示范文本库的“合同全文 + 发布机关风险提示”（602 份、3,466 条）与市场监管／法院官方案例中的人工法律分析（6 个来源、62 个案例段），见 [人工批注样本来源与爬取](人工批注样本来源与爬取_20261119.md)。这些材料只用于校准标注口径与审查要点，不能直接作为测试集标签。

### 1.2 标注单元与标签空间

| 类型 | 标签 | 约束 |
|---|---|---|
| entity | 主体、金额、日期、期限、编号等实体 | Python Unicode 半开区间；`text[start:end] == evidence`；保留重复位置与角色 |
| risk | 风险码（沿用系统风险码，不新增未定义码）与严重度 | 必须绑定原文连续片段；无原文支撑不得标 |
| law_reference | 法条条目（`provision_id`）与 0—3 相关度 | 须给出合同引文与法条引文；未判定条目不按负例计 |

标注字段与校验以 `tools/selected_solutions_20261118/human_acceptance.py` 与 `human_acceptance_usage.md` 为准；不另造格式。

### 1.3 构建流程（顺序不可调换）

1. **训练暴露清查**：整理所有已用于训练／验证／调参的合同、模板家族与来源，形成非空 `complete_training_development_inventory.jsonl`。
2. **许可与来源登记**：逐份确认公开来源与使用许可；OCR 合同先人工校对并固定原文，原文变更后重新分发、不得搬旧 offset。
3. **预注册 split**：按来源组件／项目家族／规范化全文与近重复共同分组，测试集在标注开始前固定；同项目家族不得跨 split。
4. **双人盲审**：两名标注人独立填写 A/B，不得看系统输出与对方结果；标注人身份在登记表登记。
5. **第三人仲裁**：逐条填写仲裁表；A/B 一致也要显式仲裁；空答案须人工显式确认 `empty_annotation_confirmed=true`。
6. **校验与冻结**：`validate` 通过后 `freeze` 生成不可覆盖的 `gold.jsonl` 与 manifest；源文件哈希保持一致；留出集与训练清单近重复冲突即拒绝。

### 1.4 完成判据

- 冻结 `gold.jsonl` 存在且不可覆盖；manifest 记录每行原文哈希、来源、许可、双人答案与仲裁决定。
- 训练／测试按来源与近重复隔离通过；不得为过门禁删除训练使用记录。
- 未标注、来源不明、未仲裁或空答案未确认的行不得进入正式评分。
- 在此之前，本项目对该数据只能称“待标注包”，不能称“独立人工标注目标测试集”。

## 二、三臂对比（P2）

### 2.1 控制变量（先冻结再跑）

- 同一冻结输入：人工校对后的合同原文与同一分句结果；同一 `gold.jsonl`。
- 同一模型与权重：LegalOne-8B 实际权重、GGUF 量化版本、SHA-256；同一 llama.cpp 运行时与参数。
- 同一提示与输出预算：温度 0、同一提示模板、同一上下文与最大输出 token；除臂定义差异外不得改动。
- 同一检索器与法条库版本：同一 BGE／BM25 配置、同一法条快照与生效版本。
- 同一评分脚本：实体／风险／法条引用／检索排序指标由同一脚本计算；预测与 gold 均落盘留证。
- 每份合同每臂只跑一次；超时、截断、失败原样记录，不挑选成功重跑拼接。

### 2.2 臂定义

| 臂 | 内容 | 配置开关（以实际 Config 为准，运行前固化到 plan.json） |
|---|---|---|
| A 旧模型 | 旧默认权重＋单链路审查；不启用新协作编排、逐项反馈回环与主体证据 | `enable_multi_agent=False`；按旧默认模型配置；关闭新回环开关 |
| B 单模型加检索 | 单次模型审查＋法条检索（RAG）；无多智能体编排与反馈回环 | `enable_multi_agent=False`；`enable_llm=True`；法条检索开启 |
| C 完整协作系统 | 多智能体编排＋逐项反馈回环＋主体证据＋统一融合 | `enable_multi_agent=True`；反馈回环与主体证据按默认开启 |

若某开关无法在单链路中完全关闭（代码耦合），必须在 plan.json 中如实记录“实际差异”，不得默认声称控制干净。

### 2.3 指标（全部按合同分层、按任务类型分层）

| 维度 | 指标 | 说明 |
|---|---|---|
| 实体 | 严格 span Precision/Recall/F1（实体类型＋边界） | 主指标；另报宽松匹配 |
| 风险 | 风险码 micro/macro F1；严重度一致率 | 只统计 gold 中已有风险码 |
| 法条引用 | 引用精确率／召回率（引用条是否在人工相关集合） | 与推荐排序分开 |
| 法条推荐 | Recall@1/3/5、nDCG@5、MRR、MAP | 用 `acceptance_dataset.ranking_metrics`；声明判定范围（全库或声明池） |
| 结论支持性 | supported／unsupported／unknown 比例；人工复核率、未决率 | 不计入“正确率” |
| 成本 | 调用次数、上下文字符、耗时、失败／截断率 | 次要指标，不替代法律质量 |

- 统计口径：对合同做 bootstrap 重采样给 95% 置信区间；同一合同上做配对比较。
- 预注册最小可检测效应（建议：主指标绝对差 ≥ 0.05 且 CI 不跨 0）；不达标不得称有提升。
- 没有任何实际指标时报告“未测”，不生成估算值。

### 2.4 输出

每臂：`plan.json`、逐合同预测、失败/截断记录、评分 `results.json`；汇总 `comparison.md` 只列实测指标与置信区间。无 gold 时命令必须拒绝出正式分数（沿用人工入口的拒绝语义）。

## 三、归因（P3）

1. 先算 C−B：多智能体编排＋反馈回环＋主体证据带来的增量。
2. 再算 B−A：单模型＋检索相对旧模型的增量。
3. 组件消融（仅在 C 上逐项关闭，其余保持不变）：
   - 关闭法条检索（或换成空检索）→ 检索收益；
   - 关闭 NLI 深度判别（退回规则）→ 判别收益；
   - 关闭主体证据 → 主体事实收益；
   - 关闭反馈回环（`review_max_rounds=1`）→ 回环收益；
   - 关闭多智能体融合（走单链路同模型）→ 协作收益。
4. 判定三分类：
   - 有收益：预注册主指标提升 ≥ 阈值且 CI 不跨 0；
   - 无收益：提升小于阈值，或 CI 跨 0 且成本不降；
   - 无法判定：缺数据、缺金标、样本不足或运行失败。
5. 输出按组件列出三分类与证据（指标、CI、样本量、失败率）。无法判定项不得强行归因，也不得用工程指标顶替。

## 四、针对性训练（P4）

- 触发条件：P3 明确指认某组件“无收益”或存在可训练短板，且 P1 金标已冻结。
- 数据：优先真实／人工标注；训练、验证、测试严格分离，测试仅用冻结目标测试集；合成数据只能进训练且须标注来源。
- 训练前注册：目标指标、停止条件、最大步数、随机种子、比较基线（A/B/C 中对应臂）。
- 训练后：在同一测试集上与基线比较；未超过基线或与基线不可区分，则不替换默认权重，候选权重与失败记录一并保留。
- 禁止：用测试集调参；把弱监督诊断写成目标收益；因工程接入成功而替换默认模型。
