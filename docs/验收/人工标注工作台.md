# 独立人工标注工作台

本工作台把原有 `zlql-human-gold-v1` 标准接成实际可操作的网页流程：未标原文导入、A/B 独立领取、精确证据标注、草稿保存、锁定提交、双路人工仲裁、标准校验与版本冻结。它不调用规则或模型生成标注，不自动填写金标，也不创建虚构标注人员。

**当前材料状态：现有 `待标注包_v1` 的 18 份原文是新编合成候选，仍须由真实人员标注。工作台的自动化 fixture 测试不是实际人工标注验收，不能据此宣称获得独立真人金标、真实业务测试集或人工标注准确率。** 原有候选包、A/B 空文件和 manifest 不会被工作台改写。

## 首次启动

在项目根目录使用 Python 3.10 或以上版本。下面的管理员编号必须由实际负责人填写，不能用占位编号假扮真实人员。

```powershell
$annotationAdminId = Read-Host '实际管理员唯一编号'
python tools/annotation_workspace.py init --admin-id "$annotationAdminId"
python tools/annotation_workspace.py serve --host 127.0.0.1 --port 8630
```

`init` 只在空工作台执行一次。它向当前控制台返回管理员令牌，服务端仅存 SHA-256。请由负责人妥善保存令牌，不写入公开仓库、URL、截图或申报材料。工作台已经初始化时再次执行会拒绝重置，避免覆盖已有审计链。

打开 `http://127.0.0.1:8630/annotations`，输入本人令牌。主项目 API 挂载后也提供 `/annotations` 页面和 `/api/annotations/...` 接口，主网页有独立人工标注入口。默认持久目录为项目 `data/annotation_workspace`；独立命令的 `--workspace` 可指定其他目录，主 API 的 `ZLQL_ANNOTATION_WORKSPACE` 必须设置为相同目录。

默认服务仅监听本机。分发给远程实际人员时，由部署负责人提供受控的 HTTPS 与访问控制；本工具没有远程实名认证或邮件分发服务。网页令牌只保留于当前页面内存，不写入 localStorage、sessionStorage、Cookie 或查询参数；刷新后需重新输入。

## 导入现有待标注包

管理员在网页填写名称、选择 `docs/验收/待标注包_v1/candidates.jsonl`，粘贴预先确认的统一标签手册，再点击“验证并建立待标数据集”。标签手册必须先由项目负责人确认并固定；不得包含本包逐条答案、系统输出或模型预测。创建后不可改写此版本手册，修改标准须新建数据集。

也可由管理员在本机命令行导入，令牌通过隐藏输入读取，不放入命令参数：

```powershell
python tools/annotation_workspace.py import-candidates --candidates docs/验收/待标注包_v1/candidates.jsonl --guidelines "已由负责人确认的统一标签手册.txt" --name "18份合成合同候选第一版（待实际人工标注）"
```

`--guidelines` 应替换为实际存在且已确认的手册文件。不要为通过导入随意写一段文字代替标签定义。导入只接受 `status=unlabeled`、`annotations=[]`、`reviews=[]` 的原文，并调用原有 `tools/acceptance_annotations.py validate` 检查原文 hash、来源、权限和同源组。可按相同格式导入另行独立采集、合法脱敏、来源及使用权限完整的真实合同；合成材料的来源限制始终保留。

## 真实人员独立完成 A/B

1. 管理员在“登记实际标注人员”中，为两名真实独立标注员分别登记 A、B 职责，再登记另一名实际仲裁员。三种职责的人员编号不能重复。令牌只在登记响应中返回，分别私下交给对应人员。
2. A、B 各自在自己的会话中登录，选择数据集并领取下一份任务。领取由 SQLite 写事务保护，同槽位同原文只能有一个领取者。可以点击本人已有任务继续编辑；不能查看同槽位其他领取者的结果。
3. 页面只给原文、来源和固定手册，不提供项目风险提示、规则答案、模型预测、另一路结果或仲裁标签。标注员应独立通读，不通过管理员快照或线下交流获取另一路内容。
4. 在原文中选取精确证据，填写手册中的类型与标签，点击“添加此证据标注”；也可直接编辑标注 JSON 数组。类型只允许 `entity`、`risk`、`law_reference`。`start/end` 使用原文 Unicode 码点半开区间 `[start,end)`，包括 emoji 的情况；服务端逐字核对 `evidence == text[start:end]`。
5. 点击“保存草稿”持久保存。每次写入提升 revision，旧页面、旧离线文件不能覆盖更新的版本。草稿不是人工完成结果。
6. 实际标注员完成全文复核后，亲自勾选人工完成、独立且未使用系统预测等声明，再锁定提交。确实没有标注项可提交空数组，但必须另外确认这是真实复核后的空结果，不能将未标模板当作完成。提交后不允许改写；发现疑难点在本人备注中保留，交仲裁处理。

不同账号和勾选声明仅是软件约束，不能证明账号由不同真人持有，也不能证明实际上未交流或未查看系统。管理员须在实际组织、分发和监督中保障独立性。不得同一人切换 A/B 账号来填补人工工作。管理员角色可导出含已提交结果的工作快照，因此不得兼任盲标员，也不得向尚未提交的标注员传播快照。

## 离线 A/B 文件

本人可导出 `zlql-blind-review-v1` JSONL 模板或草稿。导出仅含本人槽位及原文，不含另一路结果；同槽位其他人员已领取的任务不导出。可以在统一手册指导下离线人工编辑，再由本人令牌导入。

每条离线记录需保留 `id`、`dataset_id`、`text_sha256`、`slot`、`reviewer_id` 和 `revision`。`pending` 表示空模板，不能导入为完成结果。导入 `status=submitted` 时还须提供：

```json
{
  "schema_version": "zlql-blind-review-v1",
  "id": "保留实际原文ID",
  "text_sha256": "保留实际原文hash",
  "slot": "A",
  "reviewer_id": "本人实际唯一编号",
  "revision": 0,
  "status": "submitted",
  "annotations": [],
  "annotations_sha256": "由实际annotations计算的SHA-256",
  "notes": "由本人填写实际完成说明或疑难点",
  "method": "manual",
  "used_system_predictions": false,
  "reviewed_at": "实际完成时间，ISO 8601并含时区",
  "attestation": {
    "human_authored": true,
    "independent": true,
    "read_full_text": true,
    "used_system_predictions": false,
    "empty_confirmed": true,
    "guidelines_sha256": "保留该数据集固定手册hash"
  }
}
```

上述字段示例是格式说明，**不是可以冒充实际人工完成的标注结果**。只有实际完成后本人才能填写真实声明与时间。非空标注同样需要真实完成声明；空数组仅适用于确实没有标注项的人工判断。

hash 算法与原有标准一致：对 `annotations` 执行 `json.dumps(..., ensure_ascii=False, sort_keys=True, separators=(',', ':'))`，再对 UTF-8 字节计算 SHA-256。工作台会拒绝身份、槽位、原文 hash、标注 hash、版本或证据范围不匹配的结果。一个导入批次全成或全败。提交的原始 JSONL 文本及其 hash 保存在本地数据库 `import_sources` 中，独立的两份标注保留于最终导出 `reviews`，不会被仲裁结果替换。

## 分歧仲裁

只有同一份原文 A、B 都已提交且编号不同，实际仲裁员才能领取并看到两份完整独立结果。界面比较标注数组，提示一致或存在分歧；即使数组一致也不自动形成最终金标，备注和原文仍须人工核对。

仲裁编辑区初始为空，不自动采用 A、B 或系统结果。实际仲裁员复核原文和两路结果，填写最终 annotations 与实际理由，保存草稿或确认锁定提交。空最终数组同样需要实际确认。最终标准记录保存两份独立 `reviews`、各自人工审计字段和 hash，以及另行保存的 `adjudication` 理由、时间、人员编号与最终标注 hash。

## 校验、冻结与导出

管理员可先验证和导出“工作快照”。尚未完成的记录保持 `unlabeled` 或 `in_review`，快照明确标为非冻结金标。快照校验通过只能说明结构与当前审计字段满足检查，不等于已经有冻结测试集。

冻结必须满足：全部原文已完成双路独立人工提交及人工仲裁；提供非空的完整训练/开发来源 JSONL 清单（至少含 `text` 和 `source.group_id`）；实际确认清单完整、人工近重复/模板家族复查和冻结测试集不再用于调优。空清单或已有训练来源与本次 test 重叠会被拒绝，未标注或未仲裁数据也会被拒绝。

工作台直接执行现有 `tools/acceptance_annotations.py freeze`，不重写其分组划分与验收标准。划分使用固定种子与同源组，不能把同一合同的模板变体拆到 train/test 两边。原有标准仅检查精确及归一化重复和同源组，无法自动发现全部语义改写泄漏；近重复人工复查及清单完整性仍由实际负责人承担。

成功后生成不可覆盖的新版本目录：

```text
data/annotation_workspace/frozen/<dataset_id>/<version>/
  gold.jsonl
  training_inventory.jsonl
  guidelines.txt
  validation.json
  manifest.json
```

manifest 保留原文包、金标、训练清单、手册、验证结果及验证工具 hash、种子、版本、合成记录数量和独立性核验限制。数据集冻结后禁止继续编辑、导入或再冻结覆盖；修订必须建立新数据集/新版本。导出时重新核对 manifest 与本地冻结审计记录，并核对金标、手册、训练清单、验证结果的 hash。验证失败不导出金标。

本地 SQLite 数据库及其哈希链不能抵抗拥有操作系统和数据库完全权限的恶意管理员整体重写，不等于独立可信时间戳、外部实名认证或第三方公证。项目验收应另行保存真实人员身份与分发记录、外部来源及授权、人工复核记录、只读冻结制品备份。产品不会将 `independently_sourced_real_contracts_verified` 自动升级为 true。

## API 挂载约定

所有工作台接口使用 `Authorization: Bearer <本人令牌>`，不接受 URL 中的令牌。入口为 `annotation_workspace.handle_request(workspace, method, path, body, authorization, query)`；返回字典的数字 `status` 与现有 API 路由约定一致，错误不返回任何已创建金标。

| 方法 | 路径 | 权限与用途 |
|---|---|---|
| GET | `/api/annotations/session` | 本人身份及限制说明 |
| GET / POST | `/api/annotations/datasets` | 查看数据集 / 管理员导入未标候选 |
| GET / POST | `/api/annotations/users` | 管理员查看编号 / 登记独立职责人员 |
| GET | `/api/annotations/tasks?dataset_id=...` | 本职责任务状态，不返回其他人标签 |
| POST | `/api/annotations/claim` | A/B 领取任务 |
| GET | `/api/annotations/task?dataset_id=...&record_id=...` | 读取本人已领取任务 |
| POST | `/api/annotations/draft`、`/submit` | A/B 保存草稿 / 锁定提交 |
| POST | `/api/annotations/import` | 本人独立离线结果事务导入 |
| POST | `/api/annotations/adjudication/claim` | 仅双路提交齐全后领取仲裁 |
| GET | `/api/annotations/adjudication/task` | 本人仲裁任务及两路锁定结果 |
| POST | `/api/annotations/adjudication/draft`、`/submit` | 人工仲裁草稿 / 锁定提交 |
| POST | `/api/annotations/validate`、`/freeze` | 管理员校验工作快照 / 标准冻结 |
| GET | `/api/annotations/export?dataset_id=...&kind=...` | `blind` 本人盲标；`snapshot` 管理员工作快照；`frozen` 管理员冻结金标 |
| GET | `/api/annotations/audit` | 管理员查看操作审计链并校验 |

## 本次软件验证口径

`zhilv_qiling_v2/tests_v2/test_annotation_workspace.py` 使用临时目录和明确标为 `AUTOMATED_WORKFLOW_FIXTURE_NOT_HUMAN_GOLD` 的合成 fixture。覆盖权限隔离、不同职责编号约束、并发领取、Unicode 证据范围、版本冲突、提交声明与锁定、离线原件与 hash、批次事务回滚、未标冻结拒绝、训练泄漏拒绝、仲裁与标准冻结、冻结制品篡改拒绝，以及本地真实 HTTP 页面/鉴权/草稿往返。另有针对实际产品 `api.serve` 挂载的页面、未授权拒绝和待标数据集接口测试；模型初始化在该测试中隔离，不调用任何真实模型。

浏览器可视检查曾尝试使用已安装 Edge，但电脑操作工具因无法核验当前浏览器 URL 而停止。此项没有记为浏览器可视验收通过。真实人工仍需实际访问页面完成标注；软件 fixture 通过不能替代真实标注人员或正式数据验收。
