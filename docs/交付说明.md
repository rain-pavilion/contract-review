本项目工作区原有一个 v1 项目（`app.py` + `contract_review/` + `checks/` + `scripts/`）。
本轮升级**不改动 v1 的任何文件**（文件时间戳仍为 2026/9/17），全部新代码写在新文件夹 `zhilv_qiling_v2/` 中，
只读复用 v1 的 `data/` 语料资产。

### 论文 docx 的两个已知"出厂设置"（已处理，重跑需注意）

1. **`compatibilityMode`**：模板来自学校 `.doc`，`settings.xml` 里带 `w:val="11"`（Word 2003），Word 打开会挂"兼容性模式"、按旧规则渲染行距与表格。已改为 `15`，并把 `DocSecurity` 归零（否则会提示"以只读方式打开"）。
2. **目录页码**：python-docx 算不出分页，`TOC` 域里带的是按字数估算的静态页码（实测偏差 1–3 页）。已用 Word 更新域并保存，现在目录页码与真实页码一致（第1章 1、第2章 6、第3章 10、第4章 14、第5章 21、第6章 26、结论 32、参考文献 34、致谢 37、附录A 38、附录B 39）。

> 重新生成 docx 后跑一次 `python tools/fix_thesis_toc.py` 即可把这两件事一次补齐（幂等，可反复跑；会留 `.bak` 备份，`--no-backup` 可关掉）。

## 三、怎么跑

```bash
# 环境自检（依赖、语料、模型目录）
python -m zhilv_qiling_v2.cli doctor

# 单份审查（文本 / docx / pdf 都可）
python -m zhilv_qiling_v2.cli review samples\tech-development-contract.txt --verbose

# 法条检索
python -m zhilv_qiling_v2.cli retrieve --text "租赁期限二十年以上" --top-k 5

# 批量审查（默认扫 data/generated_contracts，可 --root 指定）
python -m zhilv_qiling_v2.cli batch --limit 10 --csv reports\batch.csv

# 爬取政府采购合同（无令牌时天津源自动降级并写 degraded 账本）
python -m zhilv_qiling_v2.cli crawl --source ccgp_beijing --limit 5 --pages 2 --use-ocr

# 训练五个组件并出报告
python -m zhilv_qiling_v2.train --only boundary,rerank,risk,calibration

# 起 Web 界面（http://127.0.0.1:8610）
python -m zhilv_qiling_v2.cli review --help
python -m zhilv_qiling_v2.api
```

## 六、推送到 GitHub（需要你手动跑，或先开代理）

```bash
# 1) 确认远端
git remote -v                     # 应为 TKFTNU/contract-review

# 2) 若本机有代理（Clash 默认 7890 / v2rayN 10809），先让 git 走代理
git config --global http.proxy  http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890

# 3) 推送（首次会要求输入 GitHub 用户名 + Personal Access Token 作为密码）
git push origin main

# 4) 推送完可以关掉代理配置
git config --global --unset http.proxy
git config --global --unset https.proxy
```

无代理时的替代路线（任选）：

| 路线 | 命令/做法 | 说明 |
|---|---|---|
| SSH over 443 | `ssh -T -p 443 git@ssh.github.com`，成功后 `git remote set-url origin git@ssh.github.com:TKFTNU/contract-review.git` | 443 端口常能绕过 22 端口封锁，但仍可能被重置 |
| Gitee 镜像 | `git remote add gitee https://gitee.com/<你的账号>/contract-review.git && git push gitee main` | 国内直连稳定，答辩演示够用；之后可用 Gitee 的"强制同步"回推 GitHub |
| 网页上传 | GitHub 仓库页 → Add file → Upload files，把 `zhilv_qiling_v2/`、`deploy/`、`tools/`、`docs/`、`.github/` 拖进去 | 只适合补几个小文件，99 个文件的提交别这么干 |

> 注：本次会话里 `git push` 被运行环境的策略拦截（认定为可能删除远端 ref 的高风险操作），所以推送这一步只能由你在本机执行 —— 提交已经在本地做好了，命令一行即可。

## 七、论文排版的落地细节（本轮格式优化做了什么）

生成器 tools/build_thesis_v2.py 与 tools/thesis_builder.py 里改了八处，全部以评委能看出来为准：

| # | 问题 | 处置 | 判据 |
|---|---|---|---|
| 1 | 三张图宽 15.0cm，超版心 14.64cm | figure() 硬性收口到 14.4cm，FIG() 默认值同改 | 图片 XML cx/360000 ≤ 14.4 |
| 2 | 13 张表全是 Table Grid 全框线 | TB() 默认 three_line=True：上下 1.5pt 粗线、表头下 0.75pt 细线、无竖线 | 逐表读 tblBorders 六条边 |
| 3 | 表中文字列被等分列宽挤成 2~3 行 | 新增 auto_column_widths()：按内容显示宽度分配，短列保底、长列承担折行 | 表 6-1 由 2.92cm 等分改为 1.50/2.31/3.10/2.50/3.69/1.50 |
| 4 | 长文本列居中，折行后读起来很碎 | 列最大显示宽度 > 12 的列改左对齐，其余居中 | _format_cell(align=...) |
| 5 | 长表跨页丢表头、单行被页边界劈开 | 每行加 w:cantSplit、表头行加 w:tblHeader、单元格 vAlign=center | 15 处 cantSplit / 13 处 tblHeader |
| 6 | 表格底线与紧随正文贴在一起 | body() 在表格后自动补 6pt 段前 | 47 页版本中该间距可见 |
| 7 | 封面「论文题目：」被首行缩进挤出单元格、折成两行 | 根因是模板样式带 firstLineChars=200，Word 按字号换算成 723tw≈1.27cm；改为清 w:ind 后重写 firstLine/firstLineChars=0 | 封面 span 单行、论文题目： 只出现一次 |
| 8 | 封面两行都印「论文题目：」、题目下方还留着一条 4 空格下划线 | 标签只写第一行；题目按结构助词断行（…协同的 / 政府采购合同…），不再从「政府采购」中间劈开；残线改为纯空段 | 题目 16pt、两行 14+17 字 |

**重跑顺序（改了内容后照这个来，否则目录页码会退回估算值）**：

```powershell
python tools\build_thesis_v2.py          # 重新生成 docx + txt
python tools\fix_thesis_toc.py --no-word # compatibilityMode 11→15、DocSecurity→0
pwsh -File tools\update_toc.ps1          # Word 更新目录页码 + 导出 PDF 预览

```

> 注：tools\update_toc.ps1 必须以 **UTF-8 with BOM** 保存，否则 PowerShell 5.1 会按 GBK 解码中文而报语法错（本轮踩过一次，已在文件里加注释说明）。
