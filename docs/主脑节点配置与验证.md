# 主脑第一的六节点协作

当前多智能体模式的核心节点编号：①主脑规划与调度，②要素抽取，③逻辑审查，④主体审查，⑤法条匹配，⑥综合评估。①分派②与③两个并列职责分支：②提取合同主要信息，③分析上下文与跨条款逻辑；再按依赖组织④主体审查、⑤法条匹配及⑥综合评估，保留③④⑤之间的反馈校验。当前执行器顺序调度，职责并列不代表实际并发，也不将②的完成作为③的必需前置条件。输入预处理与高风险复核是辅助角色。基础审查流水线仍执行五个业务阶段。

第一节点沿用 `orchestrator`。它在启动、发现风险和反馈回环时生成计划，可选择登记的逻辑审查、综合评估、专家复核模型，并提出转人工。执行器校验角色、模型、条款范围和预算，保留必需业务流程。业务节点、引文校验、确定性评分和 pending 状态不由主脑任意改写。

## 云端主脑

主脑使用已有客户端支持的 OpenAI 兼容 Chat Completions 接口。以下为变量名和示例，实际端点、模型及凭据由所选服务商提供；本次没有新建或写入真实密钥。

```text
ZLQL_MULTI_AGENT=1
ZLQL_ENABLE_LLM=1
ZLQL_ENABLE_PLANNER=1
ZLQL_PLANNER_ENDPOINT=https://your-provider.example/v1
ZLQL_PLANNER_MODEL=your-planner-model
ZLQL_PLANNER_API_KEY=由本地安全环境配置提供
ZLQL_PLANNER_TIMEOUT=45
ZLQL_PLANNER_MAX_TOKENS=1600
ZLQL_PLANNER_MAX_CALLS=4
```

仅配置主脑时，网页显示云端主脑已配置，同时明确默认法律专家尚未配置。`ZLQL_ENABLE_LLM=0` 关闭所有规划/业务模型请求；`ZLQL_ENABLE_PLANNER=0` 仅关闭模型规划，使用规则调度。配置存在不等于服务可用或模型质量通过验证。

## 专家模型池

`default` 使用 `ZLQL_LLM_ENDPOINT/MODEL/API_KEY`；`strong` 使用 `ZLQL_LLM_STRONG_ENDPOINT/MODEL/API_KEY`，强模型凭据独立设置。

`ZLQL_MODEL_POOL` 是 JSON 对象，可登记多个云端或本地专家。示例对象如下；密钥通过环境变量名引用，不写入对象：

```json
{
  "cloud_legal": {
    "endpoint": "https://your-expert-provider.example/v1",
    "model": "your-legal-model",
    "agents": ["logic", "judge", "reviewer"],
    "api_key_env": "CLOUD_LEGAL_API_KEY",
    "timeout": 90,
    "max_tokens": 1024,
    "enabled": true,
    "description": "复杂法律语义、条款分歧及高风险复核"
  }
}
```

主脑只接收模型能力卡和有界任务摘要，并返回模型 ID；端点和凭据由执行器解析。未知模型、能力不符、越界条款和错误格式会触发规则回退。选中的路由实际用于初审、反馈重跑或综合说明；切换模型时不会将旧模型的反馈复用视为新模型执行。模型池只允许配置登记的服务，不接受模型生成的新 URL。

## 失败和完成判据

- 主脑缺配置、请求失败、非法输出或预算耗尽：保留原因，使用规则计划；不标为模型成功。
- 专家复核失败：最多尝试两次，保留未完成事项，不发送成功完成凭证。
- 主脑转人工：保留报告级人工事项和相关风险的复核标记；零风险候选也不会隐藏该事项。
- 回环终止：仍按原有证据、反馈及工作账本判据；达到轮数上限或有待办不能记为收敛。
