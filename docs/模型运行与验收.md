# 模型运行与验收

当前按用户最新要求优先完成核心技术：真实模型调用、深度法条判别、跨条款上下文、逐项回环核验和主体证据入口。全量基准、吞吐与规模实验暂后置；已有历史数据保留，不能替代法律质量结论。

## 启动

- 双击 `start-core-web.cmd`：显式选择已实际训练的 BERT–Mamba 法条判别分支，并连接或启动唯一的 LegalOne-8B，随后启动网页。新分支基于合成弱监督训练，页面健康信息保留来源与非人工金标标记；缺少新权重时直接报错。
- 双击 `start-model-web.cmd`：明确启动本地 LegalOne-8B，再启动网页。默认优先使用本机已经转换的同一模型 Q4_K_M GGUF 与 llama.cpp；可显式指定 `--model-backend transformers` 使用原实现。模型加载失败会报告错误，不会用小模型冒充8B。启动器创建的模型进程日志保存在 `zhilv_qiling_v2/reports/model-server.log`。
- 双击 `start-web.cmd`：默认进入 `start-defense-web.cmd` 答辩配置，连接或启动8635端口的真实 LegalOne-8B GPU服务，再启动8618工作台；成功启动网页后保留模型常驻，后续启动复用已验证的同一服务。不会自动进入离线模式。需要关闭主模型通道时，显式使用 `start-offline-web.cmd` 或 `python start_web.py --without-model`。
- `python start_web.py` 通用命令行默认也启用主模型，默认网页/模型端口为8610/8620；`--keep-model-running` 在网页成功启动后保留本次模型服务，启动失败仍清理本次创建的模型进程。已有模型服务不由启动器关闭。
- 启动器使用项目 `.venv`（存在时），PDF补充依赖使用 `.web-deps`。依赖仅安装到项目隔离目录。
- 已有旧版离线网页进程占用8610时，先关闭旧进程，再启动增强模式。启动器不会擅自关闭未知进程或用户正在使用的软件。

命令行示例：

```powershell
.\.venv\Scripts\python.exe start_web.py --with-model --no-browser
# 硬件不足时可明确使用CPU模式；这可能非常慢，不保证三分钟目标
.\.venv\Scripts\python.exe start_web.py --with-model --quant 4bit --model-device cpu
```

模型端点默认仅监听本机，未发布公网。权重存在、模型加载成功、实际生成成功是不同状态，应分别查看运行状态与报告调用记录。

Transformers CPU 模式默认限制为4个计算线程，并检测硬件是否支持 BF16 快速指令；仅有 AVX2 时采用 FP32 计算。实际测试仍发现本机 bitsandbytes CPU 单 token 约60秒，不能用于日常网页审查，因此当前优先选择 llama.cpp CPU 8线程运行同一8B模型。四位量化会改变数值精度，验收需保留实际后端与量化配置。

本机 GGUF 为 `.model-runtime/models/legalone-8b/legalone-8b-Q4_K_M.gguf`，由原始4分片 LegalOne-8B 转换，实际8195978240参数，大小5031423744字节，SHA-256为 `55efa18b1fa1d71637cec0a50f858033e5c1fd934cfde89dcfa910faff46264d`。原始权重未改写。官方 llama.cpp b12375 CPU 包已与发布页摘要核对；源码固定在commit `9d25e0014c4b4b316873c01f4938c0e3c687287d`。来源、格式转换、量化及真实探测证据保存在 `tools/acceptance_results/legalone8b_*.json` 和 `llama_runtime_preparation.json`。

原生模型服务只监听8620本机端口，alias为 `legalone-8b`，上下文8192、单推理槽位、8线程、不启用上下文静默滑动。网页结构化审查显式使用 `native_thinking=off`、`native_reasoning_format=deepseek` 和4096输出预算；这些 llama.cpp 专用参数仅在显式配置时发送。推理文字不作为业务JSON，结束标记及最终回答边界经过独立测试。此前小型探测只证明实际生成，不是完整合同审查或准确性成绩。

可复现准备入口为 `tools/download_llama_runtime.py`（需要获准网络访问）与 `tools/convert_legalone_gguf.py`。`.model-runtime` 已忽略，不应把大型权重或运行时二进制提交到Git。

## 完整覆盖与回环

节点②按原文分块处理全部非空条款，并安排显式引用、同主题等跨条款窗口。跨条款检查是定向检查，不是所有条款对的穷尽证明。

- `ZLQL_LLM_CHUNK_CHARS`：每窗口目标字符数，默认1800。
- `ZLQL_LLM_CHUNK_OVERLAP`：长条款分块重叠，默认160。
- `ZLQL_LLM_MAX_CALLS`：模型调用预算，默认0表示不因预算截断。非零预算耗尽、模型失败、结构解析失败都会影响覆盖率并记录未审条款。
- `ZLQL_LLM_MAX_TOKENS`：每次回复的输出 token 上限，本地模型启动器默认4096。达到上限会记录截断，不能把补齐括号后的部分 JSON 当作已完成全文审查。
- `ZLQL_LLM_NATIVE_JSON_SCHEMA`：仅在支持的原生服务上启用逐批JSON Schema；启动器核实本机llama.cpp后自动开启，普通兼容网关默认关闭。约束反馈根数组和ID/长度，合同引文从实际连续原文片段提取选择；业务仍独立核对逐项引文及来源，缺证与 `needs_manual` 继续pending。该模式证明来源定位，不代表片段相关性、法律真值或自由生成引用能力；审计保留发送标记和schema hash。
- `ZLQL_LLM_CROSS_CLAUSE_PAIRS`：定向跨条款窗口预算，默认12。
- `ZLQL_REVIEW_MAX_ROUNDS`：②③④回环上限，默认3；当前反馈仍有待核验项时，不得仅因候选集合不变而提前标为稳定。失败项下轮重试，达到轮数上限后保留pending。
- `ZLQL_ENTAILMENT_BACKEND`：法条关系后端，`auto`尝试本地深度模型，失败明确降级；`rules`显式使用规则。

显式引用窗口保留引用位置原文锚点及源条款、目标条款分段，预算限制实际窗口总数。编号规范化支持“第二条／第2条”、带标题条号与数字小节；歧义、悬空引用和超预算依赖保持pending。`text_complete` 仅说明正文计划完成，`explicit_reference_complete` 说明显式依赖完成，二者同时完成才形成整体完成状态。普通主题配对仍是定向检查，不是穷举所有条款关系。

在报告“协作图谱”中查看上述覆盖状态、逐次调用结果、候选—条款—法条校验、回环轮次和终止原因。分数与覆盖率都不是法律准确率。

回环反馈每批至多3项、反馈JSON不超过4000字符。模型必须按原始反馈ID逐项返回候选ID、法条ID、结论、理由及双方连续原文引文；空 `defects` 不算核验。引文只忽略空白，保留标点，改写、错绑定、漏项、截断与 `needs_manual` 均保持pending。法条来源最多发送1000字符；来源被截断时，即使模型回应合法也只记局部核验，不能计全文完成。详见 `docs/验收/逐项反馈核验协议.md`。

`stats.logic_llm.feedback_runs` 保留所有历史尝试，`feedback_latest_runs` 保留各反馈最新尝试。`feedback_runs_complete` 表示当前有效反馈是否完成，`feedback_all_attempts_complete` 另记历史是否全部成功；失败历史不会被恢复结果擦除。审查协议完成不代表法律判断正确。

主体事实通过独立的 `subject_fact_feedback`／`subject_fact_verifications` 协议进入②，绑定主体、事实或核验请求、来源及对应条款，不冒充带 `article_uid` 的法条反馈。实际证据与法条节点的主体核验请求逐ID处理；没有来源的默认unknown按主体及对应条款汇总，保留缺证状态，不制造已知事实。它们共同进入反馈完成、失败重试与终止判定。

新增 `models/bert_mamba_entail/model.pt` 已实际训练、严格重载，并接入法条判别。结构包含共享BERT双塔、双路选择性状态空间Mamba、池化门控融合、八头交叉注意力和三分类头；Mamba参数有真实梯度和权重变化。当前Mamba是短窗口池化分支，门控为全局可学习标量，不能声称扫描整份长合同或逐token动态门控。长合同依赖由上面的窗口规划承担。

这次采用288条合成弱监督文本对做轻量训练，不是充分法律训练或独立人工评测。旧 `models/bert_entail` 保持不变，新分支通过核心启动器显式选择；加载失败可见降级，不会暗中回旧权重。神经与规则分歧保留并要求人工复核。训练证据和结构边界见 `docs/验收/Mamba实际训练与显式接入.md`。

## 主体事实证据

“运行状态”支持导入主体证据JSON。文件可以是记录数组，或 `{"records":[...]}`。不得将合同中的“本公司具有资质”直接当作外部核验事实。

每条记录应包含：

```json
{
  "subject_name": "实际被核验主体名称",
  "subject_id": "统一社会信用代码或其他可匹配编号",
  "fact_type": "license",
  "status": "unknown",
  "scope": "具体资质、许可范围或信用查询范围",
  "contract_id": "授权类有效证据必须绑定具体合同ID",
  "valid_from": "2026-01-01",
  "valid_until": "2026-12-31",
  "evidence_ref": "实际保存的证据编号或档案路径",
  "source": {
    "url": "https://example.invalid/replace-with-real-source",
    "publisher": "实际来源机构",
    "reviewer": "实际完成核验的人员",
    "verification_method": "实际采用的核验方法",
    "verified_at": "2026-11-14"
  }
}
```

上例是字段说明，不是已核验事实，不应原样导入。`fact_type`可为registration、license、authorization、credit。证据记录人工提供的来源与结论，软件不保证凭证真伪，也不会自动访问来源URL。过期、陈旧、身份不匹配、其他合同授权及互相冲突的证据保持未知或待复核。

证据编号须与当前被核验主体的身份声明明确关联。编号只出现在合同另一方或正文其他位置，不能认作当前主体匹配；同名异编号、多个可能主体及无法确认关联时保留unknown。④发给③的主体核验请求会形成逐请求结果和未解决原因，不能只记入轨迹就视为核验完成。

默认文件为 `zhilv_qiling_v2/reports/subject_facts.json`，可通过 `ZLQL_SUBJECT_FACTS_PATH` 由服务端配置。HTTP请求不能指定写入路径。

## 持久批量队列

网页一次可选择1000个文件，单文件不超过25MB；服务端每批最多100000个任务。上传完成后提交批次，任务原始文件、状态、重试次数和归档ID保存在SQLite中。

浏览器关闭后服务端继续执行。服务中断后，过期租约最多约30秒后可重新领取；超过重试上限标为失败，需检查后人工重试。旧执行者不能覆盖新租约所有者的归档。归档ID等于任务ID，崩溃恢复时优先复用已完成归档，避免重复报告。

停止队列取消待处理项，当前任务继续完成；恢复/重试保留已完成项。CSV导出会分页获取该批次全部任务，页面最多显示前1000项。

大批量目录上传：

```powershell
.\.venv\Scripts\python.exe tools/submit_contract_batch.py C:/contracts --limit 100000
# 明确启用大模型，逐份实际审查可能需要很长时间
.\.venv\Scripts\python.exe tools/submit_contract_batch.py C:/contracts --llm
```

## 时间与验收口径

报告同时保留原引擎耗时与 `stats.timings` 中的解析、准备、审查、上下文、归档和服务端总时间。浏览器请求总耗时还包含网络传输；队列等待时间另计，不能将引擎时间直接当作端到端时间。

独立人工标注集和官方基准必须使用相应验收工具、固定数据版本、模型配置与评分协议。没有实际数据、人工标注或推理输出的项目应标记待完成，不生成估算准确率。合成十万份归档与模拟队列压测只证明相应存储/调度实验，不证明十万份真实合同完成模型审查。

## 本次实际验收结论

核心修订后的最新回归、真实HTTP联调及服务健康信息以 `docs/验收/本次验收结果.md` 的“当前核心技术交付”部分为准。下述旧实验使用修订前代码或配置，保留作为历史，不作为本次版本通过依据。

反馈分批版的179字符合成合同完整上传至归档响应为124.108759秒：全文174/174字符已送入成功窗口，本轮3项法条反馈全部核验，2轮结构稳定；一个定向跨条款窗口在512 token上限截断，因此有效完整审查与三分钟验收仍为false。更早161.427465秒的一轮存在反馈上下文掉项，证据保留。不得选择其中较快或较完整的局部结果拼接成达标结论。

LawBench官方1-2 zero_shot固定前10题，默认模式与显式reasoning_effort=none的新模式均由原版评分器得到score=0.0、abstention_rate=0.0，两组均10/10在128 token处截断。两组目录、真实逐题回执、模型身份、原预测和适配器源码快照全部保留；这不是完整500题或20任务成绩。CLI与请求级思考模式的静态源码检查另存native_reasoning_mode_review.json，不能仅凭冗长输出认定思考开关失效。当前不能声称模型法律质量已通过。

人工标注可从网页“人工标注工作台”或 `docs/验收/待标注包_v1/README.md` 开始。A/B盲标、仲裁、冻结和导出入口已实现，原候选包仍未标注，没有自动生成金标。独立人工法律质量、正式全量基准、常规合同三分钟目标及真实业务吞吐尚未验收；按用户当前重点暂不扩展这些效率实验。
